日期：2026-10-25；适用工程：桌面 `备赛指南/RMTC_CPP参赛程序/`，修订版本1.1.4、比赛规则v1.1。最新实测结果见《自检报告.md》。

“未验证”表示缺少对应条件下的实测证据，不等于代码还没实现，也不表示这些测试都必须到比赛现场做。

| 实际比赛电脑运行 | 该电脑在家或实验室即可 | 若比赛用另一台电脑，需在那台电脑执行 | 能构建或载入镜像，完整练习不中断，动作与回执对齐 |

## 真实模型：本机实际操作

准备可用的兼容 `/v1/chat/completions` 的模型服务。凭据在本地终端填写，不发到聊天或写进公开源码。正式比赛仍使用裁判统一网关；下面是赛前个人练习。

终端1：

```bash
cd '/home/yuanzh/桌面/备赛指南/RMTC_CPP参赛程序'
ROS_DOMAIN_ID=73 PRACTICE_PORT=18081 ./tools/start_real_practice.sh
```

按提示输入完整上游地址、模型名和密钥。脚本启动新版练习端的 `real` 模式，默认没有陪练；先只测试自己的A车。

终端2：

```bash
cd '/home/yuanzh/桌面/备赛指南/RMTC_CPP参赛程序'
ROS_DOMAIN_ID=73 RMTC_TEAM_TOKEN=practice-A ./run.sh \
  --stage 2 --seat A --gateway http://127.0.0.1:18081 \
  --llm-budget 8 --llm-timeout-ms 15000 --log-dir logs/real_llm_smoke
```

这里8次是初次链路检查的本地成功响应预算，15秒是可配置超时；不代表模型能及时理解所有事件。跑完整事件覆盖前，按实际服务与赛前规定配置合适的预算/超时，重新开始独立练习。正式封存后不能把它当作临场算法调参入口。

打开练习页面 `http://127.0.0.1:18081`，点击开始。端口、ROS域与已有练习冲突时换成一致的独立配置；同一席位不要再开参考车或另一个参赛进程。

验收必须贯通以下链条：

1. 练习端确实是 `real`，本场本席位有真实成功记录。不能拿旧场次、mock或仅HTTP连接成功替代。
2. 本车 `logs/real_llm_smoke/bot-*.jsonl` 出现 `llm_result`，状态200、`parsed`非空、无schema错误、`accepted=true`。这只证明格式/场次检查通过，仍须下一步核对语义。
3. 按**公开公告**人工核对事件种类、绝对坐标、数值、激活Tick和结束Tick。对明确影响本车的公告，不能只返回空事实就算理解通过。人工可用独立练习配置核验真值，机器人仍不得读取配置或管理接口。
4. 核对回复是否赶在需要决策的Tick前到达。超时后继续合法移动证明回退有效，不证明该事件已及时理解。
5. 选取确实影响本车的场景，核对事件事实、`frame`中的reason/action、后续`self.last_action`和位置/血量结果。例如已知会爆炸的区域应在来得及时且可逃离时提前避开；幻术时移动回执应与反转规则一致。无影响的公告不要求强行改变动作。
6. 再逐类覆盖八种事件，并跑默认500ms/Tick的完整Stage2；核查非法动作、场次/Tick、超时降级、暂停恢复和日志。代码schema测试或固定回复不能代替真实语义验收。

如果没有模型服务和凭据，这部分暂时不能完成；无需因此等待实体赛场。当前文件已具备接入代码，尚缺实际调用证据。

## 网络与设备：分两层做

先在比赛用电脑跑本机练习；若另一台电脑作为裁判，再测试跨机器。两端使用同一个公开ROS域，允许实际DDS发现和消息传输。练习HTTP服务默认只监听裁判机回环地址，跨机器时按原教程使用SSH转发等允许方式；HTTP转发不等于转发ROS2/DDS。

判断双向通信要用自己的参赛程序和本席位公开接口：收到感知 → 动作原样回填tick/session → 后续回执确认动作执行。网页“动作Tick”单独出现不够。还需在测试网络检查暂停/恢复、断连重接和新session清理。

最后在主办方指定网络复核，因为测试局域网不能代替正式交换机、防火墙、网卡配置和场次授权。没有正式接入条件时只能保留“测试网络通过、正式网络待验收”的准确结论。
