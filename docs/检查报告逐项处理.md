## 逐项判断

## 本轮额外发现和修复

- 世界分裂结束时可能删除当前感知仍确认存在的原有墙：当前可靠观测优先于临时墙清理。
- 天使公告在点位消失后迟到，会丢掉尚有效的入点回血：保留推断依据直到最后合法入点效果到期，不重新激活点位。
- 首次缺令牌/401 后，更换有效令牌不能重试同公告：失败去重绑定旧令牌，成功公告仍去重；不重置同令牌本地额度。
- 日志目录不可写阻止启动：ROS 日志回退临时目录，审计文件不可用时明确降级；日志线程逐行刷新并检测写入失败。
- 乱序旧帧可能延长过期模型目标寿命：旧帧先过滤，异步目标以控制器已知最新 Tick 校验。
- JSON 超深嵌套风险：限制解析深度；保持大小、重复键、字段类型等检查。
- 旧模拟工具只断言最后 executed_tick：新增逐场逐 Tick 的感知、动作、下一帧回执核对，恢复测试单独报告断流缺口。
- 同步旧工作目录时，发现它的 `src/planner.cpp` 和 `src/tactics.cpp` 混入普通审查说明、额度提示文字，前者还缺失部分原代码。已备份原文件并保留差异，用本轮经验证的源码同步后在旧目录重新编译和测试。该错误不在桌面本轮参赛运行文件中。

## 红绿证据和边界

用户报告的 17 个最小回归用例在修复前为 **0 通过、17 失败**；格式重试回归在修复前为 **17 通过、1 失败**。修复后它们进入完整 CTest。原 `score_and_mission_schema` 测试中“坏任务必须丢整帧”与新的隔离约定冲突，已改为要求“坏任务被隔离且有警告”，关键 score 错误依然必须拒绝。未删减关键拒绝测试来制造通过。

最初新增测试有一个括号笔误、维护替换误改一处变量；编译失败保留在日志，修正后才计通过。首次不可写日志故障测试把同一坏 ROS 日志路径也传给了测试探针，导致探针初始化失败；节点本身已正确回退。将探针的独立日志目录修正后重新跑完整组，不把失败那轮计入通过。

23场Stage1完整跑完后，测试汇总工具的两个同名导入发生冲突，导致汇总失败。修正别名后，对保存的全部2323帧重新执行两套回执校验，2300个动作逐一对应，未更改原始结果。第一次Stage2在中断前仅记录到约450 Tick，不计为完整通过；随后以`report_final_`重跑，绕圈修复后的最终版本再以`report_release_`完整重跑。镜像复查曾使用错误路径`/app/install`，按Dockerfile改用真实安装路径`/opt/rmtc`后再核对，不将那次路径错误算作镜像启动失败。

最终B场的Tick356提交MOVE后在战斗中死亡，回执E_STATE，非法动作仍为0。协议明确规定这是合法取消；原验收器却一律拒绝E_STATE。新增4项检查并按前后血量、moved=false、计数不变收窄识别条件后，12项验收器测试通过；全部最终日志重新核对，原始数据未改。缺少死亡证据、提前阵亡提交或非法次数增加的E_STATE仍判失败。

本地 HTTP 夹具只证明格式、预算、重试和失败回退，不能证明真实模型理解公告正确。格式容错不会从自然语言中用关键词猜事件，也不接受错误场次、越界坐标或小数坐标。记录安全错误详情，不把原始模型回复任意前缀写入公开日志。

路径仍是有限记忆、每帧重新规划的启发式，单个位置保存一种候选路径，不是包含所有等待时间/未知对手动作的全局最优搜索。HP成本、任务进度收益、资源衰减是赛前固化策略参数，不是裁判公式。真实 LLM、正式网络/令牌和提交手续仍须按《未验证项怎么验收.md》验证。
