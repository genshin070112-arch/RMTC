# 1.1.4：健康期过保守与接敌循环修复

日期：2026-10-25。只处理用户主要问题报告，预算、partial、资源年龄、单路径及堡垒边界不调整。

## 确认的原因

1. 1.1.3把下一Tick自己WAIT、敌人攻击的预测损失扣在所有当前战术上，健康期也承受此惩罚。复现：HP60/80/100、两名敌人在不同方向，启用前瞻会降低当前攻击价值。
2. 接近攻击位与patrol交替时，每次patrol都重置无收益追逐计数，使8Tick退避无法触发。

新增两个测试在修改前均失败，原39项报告检查通过，见本轮RED.log。

## 最小修改

- `src/tactics.cpp`：仅当当前HP≤40、普通移动当前Tick能活、且确实还有下一Tick时使用生存前瞻。40对应两次普通20伤害，属于明确的保守启发式门槛，不是裁判规则；不依赖地图、席位或敌人ID。健康期恢复即时收益比较，不再扣假设下一TickWAIT的损失。低血量仍保留脱离火线与战后治疗估值。
- `src/planner.cpp`：追逐已经开始后，中间patrol继续累计无伤害时间；有实际伤害增长、换其他目标或Tick不连续时重置。仍用既有8/12Tick退避，不扩大冷却，不禁止冷却期可直接兑现的攻击。
- `include/rmtc_bot/planner.hpp`：同步用途注释；测试在 `tests/test_report.cpp`。

## 验证范围

保留上一版144种低血量组合及天使选择、濒死即时防御、健康攻击等测试。新增健康多敌人前瞻范围与接近/巡逻交替退避测试。A/B/C/D保持上一版地图和席位，完整运行500动作Tick并核对回执、非法动作、攻击次数、最终D与得分；结果在《自检报告.md》。不根据个别地图成绩继续调权重。

该修改不承诺对任意对手最优；HP41以上也可能遇到多敌人致命威胁，当前战斗模型仍参与即时防御选择，但不再承担下一TickWAIT的假设惩罚。真实LLM和正式网络仍待验收。
