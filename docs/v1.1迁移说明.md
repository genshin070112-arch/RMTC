# v1.1 规则迁移说明

本文记录2026-10-23从旧规则到v1.1的初次迁移（当时代码1.1.0）。当前修订为1.1.4；后续错误修复见《检查报告逐项处理.md》，最新复验结果见《自检报告.md》。下列初次迁移信息不代替当前交付校验。

## 规则依据与资料冲突

逐条对比了 `校内赛/新规则/` 下三份 PDF 和旧版 PDF：赛事规则 v1.1、通信协议 v1.1、裁判测试端使用教程 v1.1。精确文件名、绝对路径、SHA256 在 `evidence/v11_rule_sources.json`；提取文本、去除排版差异后的逐行差异在 `evidence/v11_requirements/`。其中规则 PDF 第18页的原始渲染也已保留，已核对计分公式。

**新版练习压缩包校验通过，但其中 rules.txt 和 CONTESTANT_PROTOCOL.md 部分仍是旧版文字。** 它们不能覆盖新版 PDF；包内 README 已采用新计分说明。新版裁判的8个独立固定动作场景与 PDF 的新计分一致。没有修改主办方原始资料，也没有用旧练习包的运行结果冒充新版验证。

## 实际修改的文件

新增独立 C++ 模块：

- `include/rmtc_bot/scoring.hpp` / `src/scoring.cpp`：规则常量、单批次比例贡献、去重奖励、预测D与对抗分。
- `include/rmtc_bot/tactics.hpp` / `src/tactics.cpp`：比较攻击、防御与主动踩辣椒；两种可见对手假设取较低收益。

更新生产代码：

- `src/planner.cpp`：替换只按敌方血量选攻击的规则，考虑死亡代价、反伤分奖、辣椒收益、500点门槛和动态伤害任务；保留采集与路径规划。
- `include/rmtc_bot/protocol.hpp` / `src/protocol.cpp`：明确本帧权威D字段，保留小数/下降/超500，不二次结算。
- `src/events.cpp`：去掉“辣椒触发点必使自己损血”的统一惩罚；交点对自己的该条火线免疫，其他未知火线不凭空假定发生。这也纠正了旧版已有的不准确启发式。
- `src/prompts.cpp`：加入v1.1计分、反伤/辣椒奖励、环境死亡和伤害任务说明；仍只解析公开自然语言，不直接生成动作。
- `src/gateway.cpp`：模型请求快照增加裁判最新score及本车alive/protected；HTTP、鉴权、额度与异步队列保持原接口。
- `CMakeLists.txt` / `package.xml`：版本1.1.0、新模块、第三个测试程序及仅测试使用的探针。
- `run_container.sh`：改用镜像标签`rmtc-cpp:1.1`。

更新验证和接入辅助文件：

- `tests/test_core.cpp`：先在旧算法上复现三项失败，再验证新策略；增加D下降、小数、超上限与任务保留检查。
- `tests/test_gateway.cpp`：核对实际发出的模型请求携带本帧积分。
- `tests/test_scoring.cpp`（新增）：计分、分奖、顺序、反伤、辣椒、预测与真实状态隔离检查。
- `tests/referee_probe.cpp`（新增）：人工独立验收专用多席位固定动作探针；仅测试构建，不安装进参赛程序。
- `tools/verify_v11_referee.py`（新增）：人工部署独立测试、调用C++探针，对照真实裁判感知。它不属于参赛策略。

## 预测与真实状态分开

机器人直接使用当前感知的`score.effective_damage`，不根据HP变化重建积分，不把本地估计写回，不对模型提供的推断结算真实积分。

`resolve_batch`只用于候选动作收益预测。它能够表达同批次贡献与分奖规则，但战术评估不是整个裁判的复制品：它不知道对手本Tick的真实动作、移动后位置、未知火线、场外状态，亦不会重建当前激活事件的完整强制复活过程。世界分裂、爆炸等真实结算由裁判负责，程序按最新感知恢复，优先提前规避公告危险。

战术层以“维持最近防御”和“可见敌人转为攻击本车”两种假设比较，取较低收益。它不保证覆盖全部对手行为；辣椒预测以本车成功入点和可见目标仍在火线上为条件，争格、他车移动或隐藏触发可改变实际结果。完成任务只认裁判ID，预测达标不自行登记完成。

## 复验命令与安全分工

```bash
./build.sh
ctest --test-dir build --output-on-failure -V
./tools/check_seal.sh
```

新版练习包启动示例（须在它自己的目录执行）：

```bash
ROS_DOMAIN_ID=87 RMTC_INTERNAL_DOMAIN_ID=88 ./start_referee.sh --stage 2 --port 18113
```

回到本工程，再做**独立人工验收**：

```bash
python3 tools/verify_v11_referee.py --url http://127.0.0.1:18113 --domain 87
```

这个脚本会重新部署练习场并控制专用测试席位，不能与完整对抗、参赛程序或陪练共用该裁判。不同suite应串行，或使用独立端口、公开域和内部域。本轮曾错误复用B场裁判，中断记录已保存并排除，通过结果仅来自随后完整重跑。

8个手算对照场景使用100ms/Tick加速验证机制；完整对抗另以正式默认500ms/Tick跑满500Tick。探针不调用Planner，不替代自己的参赛程序；正式场只运行`rmtc_node`，不得使用探针、管理API或观赛真值。

真实模型尚无凭据，所有本轮网关实际练习请求为mock；正式AI资格、真实自然语言理解与现场网络仍未验证，详见当前自检报告。
