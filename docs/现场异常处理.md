# 现场启动与异常处理

本页对应程序 1.1.4，规则仍为 v1.1。参赛逻辑、网关客户端和 JSON 处理均在 C++；人工离线验收工具不进入参赛进程。

## 启动前

必须明确指定阶段，遗漏会报错退出。第一阶段用 `--stage 1 --seat A`，第二阶段用 `--stage 2 --seat 裁判席位`。阶段默认时长分别为 100/500 Tick；只有官方改变时长时才修改 `--max-ticks`。应用参数放在 `--ros-args` 前。ROS launch 同样必须提供 `stage:=1` 或 `stage:=2`。

```bash
cd '/home/yuanzh/桌面/备赛指南/RMTC_CPP参赛程序'
./tools/check_seal.sh
sha256sum -c delivery_checksums.sha256
ROS_DOMAIN_ID=裁判指定域 ./run.sh --stage 2 --seat 裁判席位 \
  --gateway http://裁判地址:8000 --token-file .secrets/team.token
```

占位文字需要换成裁判给定值。`ready` 会显示阶段、最大 Tick、席位、域、RMW 和日志路径；它仅证明程序启动。收到本场感知且后续 `self.last_action` 对应自己发出的动作，才能证明双向联调。

## 终端诊断及处理

| 诊断 | 程序行为 | 人工处理 |
|---|---|---|
| `no_initial_perception_check_domain_seat_network` | 启动 3 秒未收到可用感知，提示一次 | 检查裁判是否就绪、域、席位、网线/虚拟机和 DDS 配置；不要把 `ready` 当作联调成功 |
| `no_recent_perception_no_stale_actions` | 不按旧 Tick 补发动作，等待新感知 | 裁判暂停也会出现；先确认暂停状态，再排查网络 |
| `perception_resumed` | 新感知到达后继续，无需为断流自动重启 | 看当前 session/Tick 与后续动作回执 |
| `missing_action_receipts_check_bidirectional_DDS` | 收到感知但连续缺少对应动作回执时提示；错误回执也算通信确认 | 检查发布方向、席位是否被占用、裁判拒绝原因；查看原始日志 |
| `perception_invalid` | 拒绝无法可靠解释的关键帧 | 保存错误和 Tick，向裁判说明；关键几何错误不会被当成空地 |
| `mission_*_ignored` | 单独隔离格式错误任务，继续可靠的基础决策 | 保存该场感知与诊断，检查任务格式 |
| `model_schema_partial` / `model_schema_invalid` | 最多追加 2 次格式重试；中间结果仅诊断，最终一次才提交合格条目，基础动作继续 | 查看 `detail`、`attempt`、`provisional`；最终部分结果另看 `parsed.validation_warnings`；格式通过仍需检查语义 |
| `missing_token` / 401 | 不进行无效认证请求；同公告在新令牌到位后可重试 | 只通过本地令牌文件更新裁判发放的接入凭据，不发到聊天或公开日志 |
| 网络超时、429/5xx | 后台有限退避重试；达到上限后本地策略继续 | 排查正式网关；额度耗尽不会被程序重启重置成合法新额度，资格以裁判记录为准 |
| `planner_failure` | 可靠帧下缓存合法 WAIT，避免重发上一 Tick 的动作 | 保存日志；比赛中不得擅改算法，是否重启按裁判批准流程 |
| ROS 日志目录不可写 | 启动脚本回退 `/tmp/rmtc-ros.*` 并显示目录 | 赛后及时另存，容器临时目录退出后可能丢失 |
| `audit unavailable` / `audit write failed` | 参赛动作继续，文件证据不完整，终端明确报告 | 排查权限/磁盘；不可据此声称本地证据齐全 |

## 合规边界

程序不会因网络断开而自动重启、改域、换席位或修改策略。真实比赛的重启登记、暂停窗口与裁判批准仍由队伍负责。换新场次会清除旧规划和事件，旧场次帧不会重新激活；同 Tick 重发只重放缓存动作。

`decision_config.json` 只允许已登记的 `decision_type`，同场程序最多应用两次变更。必须先得到裁判批准并处于允许窗口，不能输入坐标、目标 ID、具体动作或现场改 Prompt。

## 离线复验

```bash
./build.sh
ctest --test-dir build --output-on-failure -V
ROS_DOMAIN_ID=103 bash tools/verify_resilience.sh evidence/manual_fault_normal normal
ROS_DOMAIN_ID=103 bash tools/verify_resilience.sh evidence/manual_fault_unwritable unwritable
```

域 103 仅为隔离练习示例，不要与正式裁判或其他机器人共用。故障探针发出合成感知，只能离线运行；不安装进参赛镜像。它不替代真实模型、跨机网络或赛场验收。

容器默认接上 `tools/set_token.sh` 生成的 `.secrets/team.token`，文件只读挂载，命令行 `--token-file` 可显式指定其他容器内路径。`receipt_observed_for_sent_tick=true` 只证明对应回执已收到；`E_BLOCKED`/`E_STATE` 仍需看执行原因，不能写成动作成功。
